Merge duplicate issues in one window of a code-review issue list for the repository at $checkout, which is your working directory.

The window below holds $count issues, one per line: key | severity | number of findings | location | title -- longest finding text. The full list covers the whole codebase and is ordered so that similar issues sit near each other.

$issues

Return groups of issues that describe the same defect, so that one code change fixes every issue in the group. That covers one defect reported at different places, such as a caller and its callee, a writer and a reader, or a test and the code it tests, and one defect reported in different words. Keep issues apart when each needs its own change, even when they share a pattern, a file, or a theme, for example the same missing timeout in two independent fetch calls, or two different missing tests.

Rules:
- Each group has at least two keys. Leave an issue out of every group when nothing else in this window describes the same defect.
- A key appears in at most one group. Use only keys that appear in this window.
- title is one line of at most 15 words naming the defect.
- location is the path:line of the most representative member, copied from its line.
- Judge from the text above. Read source code only when two lines leave unclear whether one change fixes both.

Do not modify any file.
